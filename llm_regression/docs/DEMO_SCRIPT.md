### ⚠️ 如果看到 30 条全是 "实际 502" 失败

**这是代理坑，不是项目坏了。** 现象：终端里 30 条全红，错误写着 `实际 502`。

原因：终端里设过代理环境变量（比如为了 GitHub 授权设的 `$env:HTTPS_PROXY`），
程序会把**连本地 Mock 的请求也发给代理**，代理转发失败就返回 502。

**解决（复制粘贴执行）：**

```powershell
Remove-Item Env:HTTP_PROXY, Env:HTTPS_PROXY -ErrorAction SilentlyContinue
.\.venv\Scripts\python.exe llm_regression\run_tests.py
```

**检查是否设了代理：**

```powershell
Get-ChildItem Env: | Where-Object { $_.Name -match 'PROXY' }
```

有输出就说明设了 —— **跑 Mock 前必须清掉**（真实接口那条反而需要代理，注意区别）。

### 3. 把报告文件提前在资源管理器里定位好

VS Code 左侧 → `llm_regression` → `reports` → 右键 `latest_mock.html` → **在文件资源管理器中显示**

# 提问怎么答（重点准备 Q1）

## Q1 ⭐「测试都通过了，为什么还说发现了 6 个缺陷？」

**这是最可能被问的，务必背熟。**

🎤 **"这是两回事，我说清楚一下。**

**测试通过的意思是：接口的行为，和我记录的预期是一致的。**

**但那个接口本身有个毛病 —— 它对空输入、超长内容不做任何校验。**

**我一方面把它的真实行为记录成用例，让回归能稳定跑；
另一方面，把这个'应该校验却没有校验'的问题，单独提成了缺陷单。**

**所以准确的说法是：自动化回归体系是通的，
而被测接口本身有 6 个待改进的问题。"**

## Q2「AI 回答每次都不一样，你怎么测？」

🎤 **"不去断言 AI 说了什么，只断言确定的东西：状态码、JSON 结构、字段类型、
业务错误码、耗时阈值、内容非空。契约没坏，测试就稳定。"**

## Q3「为什么要自己搭一个假的接口？」

🎤 **"真实接口慢、要花钱，而且超时、服务端报错这些异常情况没法稳定复现。
自己搭的接口可以按要求模拟，所以异常分支才能常态化回归。"**

## Q4「为什么有两套用例数据，标着'契约口径'和'实测口径'？」

🎤 **"'契约口径'是我认为应该有的行为，比如空输入应该报错。
'实测口径'是这个接口实际的行为，空输入它返回成功。
两套都留着，一眼就能看出它哪里该做校验但没做 —— 这就是那 6 个缺陷的来源。"**

## Q5「这个项目有什么不足？」

**主动承认不足会显得更专业，别硬撑。**

🎤 **"有三个明确的不足：**

**第一，安全场景的自动化断言不够严谨。我原本想断言'返回内容里不能出现可执行代码'，
但实测发现 AI 会复述用户输入，会导致必然误报，所以我把它降级处理了。
这块需要单独设计用例，目前是空白。**

**第二，性能基线是经验值，还没有按真实分布做统计标定。**

**第三，密钥错误这类权限场景还没覆盖。接口已经支持，补数据就能接入。"**

## Q6「别人能直接用吗？」

🎤 **"可以。框架是分层的，新增一个接口只需要加一份配置和几行用例数据，
不需要改代码。接入方法我写在项目文档里了。"**
